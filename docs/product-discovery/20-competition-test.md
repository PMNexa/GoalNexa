# 20 — Competition Test: New Market Space vs. Competing Better

For each concept in [14 — Blue Ocean Concepts](14-blue-ocean-concepts.md): does it create new market space (converts noncustomers, competes on different factors) or does it just compete better within the existing market (wins the same customers on the same factors, incrementally)? Per Blue Ocean Strategy's own logic, concepts in the second category get eliminated from further consideration here — they may still be reasonable product decisions later, but they are not the point of this discovery process.

## Eliminated — competing better, not new market space

| # | Concept | Why it's elimination, not blue ocean |
|---|---|---|
| 8 | SSO-Native by Default | [05 — Competitor Map](05-competitor-map.md) confirms HabitSync already ships OIDC/SSO. This is matching an existing competitor's feature, not creating new demand. |
| 9 | Notify, Don't Nag (Apprise) | Same issue — HabitSync already integrates Apprise ([05](05-competitor-map.md)). Table stakes to match, not a differentiator. |
| 11 | Git-Native Goal Templates | Competes within the *existing* Notion-template marketplace ([04 — Current Solutions](04-current-solutions.md)) on file format alone — same customers, same job, marginally different delivery mechanism. Not a new market. |
| 14 | Data Ownership Passport | Every self-hosted competitor in [05](05-competitor-map.md) already markets "your data stays yours" (mhabit: *"Zero vendor lock-in... your habit data always stays yours"*). Formalizing this into a spec strengthens an existing claim rather than creating a new one — differentiation-by-degree, not by kind. |
| 16 | Streakless Mode | A UI/default-setting variant along an axis ([08 — Strategy Canvas](08-strategy-canvas.md)) several competitors (Way of Life, BeaverHabits) already occupy to varying degrees. Incremental positioning, not new demand. |
| 17 | Sponsor-a-Feature Roadmap | Per [17 — Demand Creation](17-demand-creation.md)'s own analysis, this mainly retains/monetizes *existing* users rather than converting noncustomers — a legitimate business-model tactic, but not a market-space-creating move on its own. |

**Six concepts eliminated.** Note that two of these (#8, #9) were flagged in [14](14-blue-ocean-concepts.md)'s own text as "only HabitSync does this today" — the ideation phase was already partly self-aware these weren't fully blank-slate ideas; this pass makes that judgment explicit and final rather than leaving it ambiguous.

## Survives — creates genuine new market space

| # | Concept | New space created |
|---|---|---|
| 6 | Migrate-from-Notion Wizard | Competes against non-consumption/inertia (Tier 3 noncustomers), not other trackers |
| 3 | One Instance, Two Layers | No competitor combines personal + team layers ([05](05-competitor-map.md)) |
| 18 | Solopreneur Tier | Segment below every strategic group's floor ([12](12-strategic-groups.md)) |
| 15 | Quantified Team (auto OKRs) | No competitor auto-computes key results from existing tooling |
| 2 | Stake & Self-Host | No self-hosted competitor offers a commitment-device mechanic |
| 4 | Auto-Habit passive capture | No tracker in this category does passive/automatic capture |
| 10 | Pay What You Fail (charity) | Same space as #2, routed around payment-holding liability |
| 13 | Managed-Install Consultancy Kit | New buyer type (the SMB via a partner) and channel, not a product feature competing on the existing curve |
| 12 | Compliance Mode | Targets the regulated-niche segment [06 — Pressure Test](06-pressure-test.md) flagged as genuinely untested by any competitor |
| 1 | Homelab Widget | New distribution surface (dashboard-embedded) rather than a standalone destination |
| 5 | Bus-Factor Dashboard | New competed-on factor (maintenance transparency) no competitor uses |
| 7 | Federated Accountability Pods | No product federates social/accountability features across independently self-hosted instances |
| 19 | Ambient Physical Display | New interface category (off-screen) entirely absent from the competitive set |
| 20 | Verified Referee Network | Decentralized version of a mechanism (StickK's referee) no self-hosted competitor has attempted |

**Fourteen concepts survive the test** — but surviving "is this new market space" is a necessary, not sufficient, condition. [18 — Blue Ocean Score](18-blue-ocean-score.md) already shows several of these (Federated Pods, Ambient Display, Verified Referee) pair high novelty with very low Market Potential — uncontested precisely because the addressable population is tiny. New market space and *worthwhile* new market space are different questions; this document answers only the first.

## Strategic read

INSIGHT — the elimination round removed exactly the concepts in [14](14-blue-ocean-concepts.md) that were framed as *reinforcing an existing trust/ownership claim more strongly* (SSO, notifications, data passport, template format) rather than *changing what's being competed on*. That's a useful pattern: ERRC "Raise" moves (per [09](09-errc-grid.md)) are legitimate value-curve work but are the category of move most likely to fail this specific test, because raising an existing factor — by definition — still competes on that same factor, just harder. The concepts that survive skew toward ERRC's "Create" column and the alternative-industry imports from [11](11-alternative-industries.md) — consistent with [09 — ERRC Grid](09-errc-grid.md)'s own closing insight that Create was "the closest this discovery process gets to an actual blue ocean move."

**RECOMMENDATION:** carry forward the 14 surviving concepts into [21 — Willingness to Pay](21-willingness-to-pay.md), but weight the analysis there toward the five that also scored well in [18 — Blue Ocean Score](18-blue-ocean-score.md) and were stress-tested in [19 — Strategic Fit](19-strategic-fit.md) — novelty alone, as this document shows, is not evidence of a viable opportunity.
